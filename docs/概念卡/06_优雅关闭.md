## 概念卡 6：优雅关闭 —— 收摊不是"关灯走人"

**是什么**：优雅关闭 = 给线程一个「你可以走了」的信号，让它们把手上的活和队列里的活干完再退出，最后主线程用 `pthread_join` 一个个等回来。落到代码是三件事：`stopping` 标志（表达"状态是下班了"）、`pthread_cond_broadcast`（把这条消息送到**所有**睡着的人）、`pthread_join`（等他真的走完）。缺任何一个都收不了摊：没标志 → 叫醒了也不知道为啥要醒；用 `signal` → 只叫醒一个，其余继续睡；不 `join` → 主线程接着 `taskq_free`，把别人还在用的锁 destroy 掉。

**为什么**：三条硬理由。
① 睡在 `pthread_cond_wait` 里的线程**不会自己醒**：它等的条件是「有新任务」，而收摊不是新任务，所以必须有人按闹钟 —— 光改状态没人看得见。
② `signal` 只保证「至少叫醒一个」：4 个 worker 睡同一条队列时，一声 `signal` 只走一个，`join` 永远等剩下 3 个。这就是把 `broadcast` 换成 `signal` 后段 B 必卡死（退出码 124）的原因，也是这条验收唯一能区分两者的办法。
③ **收摊 ≠ 丢任务**：队列里还没干的活要干完，所以出口条件是「已收摊 **且** 队列空」，不是「已收摊就走」。

**我代码里的位置**：`src/pool/task_queue.c` —— `taskq_stop` 在锁内 `stopping = 1` 再 `pthread_cond_broadcast`；`taskq_pop_wait` 的睡条件是 `while (count == 0 && stopping == 0)`，醒来时若 `count == 0` 就返回 -1（这时候只剩"下班了"一种解释）。`src/pool/test_pool.c` —— `worker()` 的 `while (pop_wait == 0)` 拿到 -1 就自然退出；段 A 先压 20 个 20ms 慢活、30ms 就收摊，验证"不丢活"；段 B 让 4 个 worker 先睡够 100ms 再收摊，验证"一声广播全叫起"。收尾顺序固定：`stop` → `join ×4` → `taskq_free`。证据 `verify/wsl-tq-stop-check.sh`：构建零警告、退出码 0、任务行数 20、`executed=20`、`size=0`、`joined=4` 出现 2 次；变异 `broadcast → signal` 退出码 124（卡死）。

**易错点**：① **锁外置标志 / 锁外广播** —— 消费者「判条件 → 真正睡下」之间有缝，广播正好插进去就丢了唤醒，表现是偶发关不掉（跑 1000 次挂 1 次那种），必现不了；两件事都得在锁内。② **判睡用 `if` 而不是 `while`** —— 虚假唤醒 + `signal` 只叫醒一个，醒来的线程可能面对空队列，`if` 会直接去取一个不存在的任务（读出上一轮残值）。③ **看见 `stopping` 就返回 -1** —— 队列里剩的活被静默丢掉，段 A 的 `executed` 立刻小于 20，而且不会报错。④ **`join` 之前就 `taskq_free`** —— 另一个线程可能正持着锁，这时 `pthread_mutex_destroy` 是未定义行为，通常直接崩或挂死；`join` 返回才是"没人再用它了"的证据。⑤ **以为 `stop` 会立刻返回** —— `stop` 只负责发通知，等全部线程真退出的是 `join`；某个 worker 卡在慢任务里时 `join` 就陪着等，生产上得配超时或取消点（V2）。

**面试追问**：「`stop` 只置标志、不广播，行不行？」—— 不行，睡着的人不会自己醒来看标志。再追「那为什么用 `broadcast`」—— 收摊是所有人的事，`signal` 只保证叫醒一个，剩下的会一直睡到 `join` 卡住。再追「怎么保证不丢任务」—— 出口写"收摊**且**空"，队列空了才走，所以 20 个慢活照样全干完。再深一层「正在跑的慢任务怎么办、关一次要多久」—— V1 就等它跑完（任务都很短），V2 要给业务加取消点或关闭超时，否则一个长事务能把关闭拖到超时。
