## 概念卡 2：阻塞与非阻塞（EAGAIN）

**是什么**：socket 默认是阻塞的 —— `recv`／`accept` 在本该拿到数据却还没有数据时，会停在那一行不返回，进程睡在那里等。用 `fcntl(fd, F_GETFL)` 取回当前的 flags，再用 `fcntl(fd, F_SETFL, flags | O_NONBLOCK)` 打开非阻塞位后，同样的 `recv` 在没有数据时立刻返回 `-1`，并且 `errno == EAGAIN`（Linux 上与 `EWOULDBLOCK` 同值，都是 11）。这不算出错，它的意思是"现在没有，待会儿再来"。
**为什么**：要在一次 epoll 事件里把一批字节读干净，程序必须能判断"读完了没有"。阻塞 socket 表达不出"没了"这个状态 —— 它只会卡在 `recv` 上等下一条数据，整条 IO 线程停摆（CPU 0%、其他连接全饿着）；非阻塞把"没数据"变成一个立刻能拿到的返回值，读循环才有出口。一句话分工：**epoll 负责"什么时候该读"，非阻塞负责"读的时候不许卡住"**，两者必须配套。
**我代码里的位置**：`sandbox/epoll_server.c` 里 `accept` 之后、登记进 epoll 之前的三行 `fcntl`（`F_GETFL` 取原状 → `F_SETFL | O_NONBLOCK` 写回），以及 `else` 分支里的读循环（`m > 0` → `continue` 继续读；`m == 0` → 对端 FIN，`EPOLL_CTL_DEL` + `close`；`m < 0` 且 `EAGAIN` → `break` 回 `epoll_wait`；`EINTR` → `continue` 重读；其余 → `perror` + `DEL` + `close`）。验收证据：客户端分 3 批发 `AAA`／`BBB`／`CCC`，屏幕打出 `累计 3` → `累计 6` → `累计 9`，最后 `断开了，累计 9 字节`；改成一次发 `AAABBBCCC`，只打一行 `读到 9 字节，累计 9`。
**易错点**：① `errno` 只在返回值表示失败时才有意义，成功返回后它保留的是上一次的残留值，所以必须"先看返回值、再比 `errno`"；② `EINTR`(4) 是"被信号打断"，该 `continue` 重读，不能当故障去关连接；③ `EAGAIN` 只说明这一次读空了、连接还活着，必须 `break` 回事件循环，不能 `close`；④ 写 `fcntl` 时用 `flags | O_NONBLOCK` 在原状态上多开一位，不要直接 `F_SETFL, O_NONBLOCK`；⑤ 忘了设非阻塞就写读循环，缓冲区读空后会永久卡死，现象是"程序不崩、也不动了，CPU 0%"。
**面试追问**：「epoll 水平触发本来就会重复叫你，为什么还要非阻塞？」—— LT 只保证"还有数据时会再叫我"，它保证不了我一次 `recv` 就把一批读完（一次最多读 `sizeof buf` 字节，还可能只到半条消息）；只有非阻塞 + 读到 `EAGAIN`，才能确认"这个 fd 此刻确实空了"，这也是换成 ET（只提醒一次）之后不漏数据的唯一前提。「`EAGAIN` 和 `ECONNRESET` 怎么区分处理？」—— 前者是状态，`break` 回去继续等，不删不关；后者是连接已被内核判死，必须 `EPOLL_CTL_DEL` + `close` 把资源还回去。
> 自证 2026-10-18：本机跑出 `EAGAIN=11 EWOULDBLOCK=11 EINTR=4`；两个客户端并发时累计各 6 字节、fd 5/6 不串。
