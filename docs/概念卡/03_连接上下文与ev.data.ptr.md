## 概念卡 3：连接上下文与 ev.data.ptr

**是什么**：`epoll_event` 里的 `data` 是一个 8 字节的 union（`epoll_data_t`；本机 `sizeof(struct epoll_event)` 实测 12 字节，另外 4 字节是 `events`），同一时刻只能装一样东西：一个 `int`（`data.fd`）、一个 `void *`（`data.ptr`）或一个 `uint64_t`。你在 `epoll_ctl(ADD)` 时往里放什么，`epoll_wait` 把那个事件还给你的时候就**原样还回来**，内核不解释、不复制、不检查。于是可以把它当"快递单上的取件凭条"：登记时把这条连接的地址塞进去，事件回来时直接拿到 `struct conn *`，不用再拿 fd 去查表。

**为什么**：用 fd 当数组下标（`total[conn_fd]`）能跑，但三件事一起坏。① **表容量被"最大 fd 号"绑死**：本机 `ulimit -n` 是 10240，fd 可以一路涨到 10239，`total[1024]` 根本装不下 —— 一旦哪天真漏了上界检查，就是**数组越界写**（`total[]` 在栈上，写坏相邻变量或返回地址 → 随机崩溃或被悄悄改掉的数据）。② **一个字段就得一张表**：要加读缓冲就是 `char buf[MAX_CONN][4096]`，再加切包状态是第三张，三张必须永远同步。③ **fd 是内核发的编号、而且会复用**：旧连接的状态残留只能靠"每条连接每个字段都记得清零"来兜。换成"连接上下文 + `ev.data.ptr`"之后：状态挂在自己的结构体上（加字段只加一行）、容量由池子决定（与 fd 号无关）、借出时统一清零一次。

**我代码里的位置**：`sandbox/epoll_server.c` —— 文件顶部 `struct conn` / `conns[]` / `conn_alloc()` / `conn_free()`；门的登记 `ev.data.ptr = NULL`；事件循环第一行 `struct conn *c = evs[i].data.ptr;`；`if (c == NULL)` 走 accept 分支（`c = conn_alloc()` 放在 fcntl 之后 → `c->fd = conn_fd` → `ev.data.ptr = c` → `EPOLL_CTL_ADD`）；`else` 分支 `int fd = c->fd;`；两个关闭分支都在 `close(fd)` 之前各调一次 `conn_free(c)`。验收证据：`verify/wsl-epoll-conn-accept.py` 5 条 PASS、exit 0（提交 `f6aba7e`）—— 其中「新连接 c 第一次读到数据累计 4（槽位从 0 起算）」证明"借出时清零"，它备注的「c 复用 b 的 fd 6」证明"fd 被复用不再带出旧状态"。

**易错点**：① `conn_alloc` 里不清 `total` → 新连接借到旧槽，第一次读 4 字节却打出 `total=7`（上一个连接残留的 3），验收脚本 FAIL「期望 4」；② 漏了 `conn_free` → 槽位只借不还，占满 1024 个以后 `conn_alloc()` 返回 `NULL`，之后每条新连接都被立刻 `close`，客户端表现是 "连上就断"，而服务端不崩、不报错 —— **现象：新连接 `accept()` 成功却被立刻 `close`，客户端刚连上就读到 EOF、永远收不到数据；而服务端一个报错都不打（池子满是程序内部状态，你没有地方输出它），只能靠往 `conns[]` 里数 `used == 1` 的槽，才发现已经满了。所以这条的第二个坑是「没有可观测性」，得自己补一条拒绝日志或计数。**；③ `conn_alloc` 若放在 fcntl 之前，fcntl 失败那条 `continue` 就没有归还 → 每个失败连接漏一个槽；④ union 是"二选一"：门用 `data.ptr = NULL` 登记，连接就必须也用 `data.ptr`；混用 `data.fd` 会把一个只有低 4 字节确定的 `int` 当 8 字节指针解引用 → 段错误或写到野地址；⑤ 把 `ev.data.ptr = c` 写在 accept 里、却在 `epoll_ctl(ADD)` 前又拿 `ev` 登记别的东西，事件回来 `c` 会指向上一条连接 → 数据算到别人头上（串号）。

**面试追问**：「为什么用静态数组池，不每个连接 `malloc` 一个 `conn`？」—— 三个理由：**地址稳定**（epoll 的就绪队列里可能还留着这条连接已经过期的事件，`free` 之后再解引用就是 use-after-free）、**零系统调用**（借/还都是内存操作，工业场景要可预测的延迟和内存峰值）、**容量确定**（内存上限编译期就固定，不会随连接数抖动）。代价是容量固定，超了必须显式拒。

**追问第二层：「池满了你怎么办？」**
`conn_alloc()` 返回 `NULL` 就直接把新连接 `close()` 拒掉，不在循环里等；打条日志记下拒绝了多少（注意：现在的 `accept(listen_fd, NULL, NULL)` 拿不到对端地址，要记「是谁连的」得把第二个参数换成 `struct sockaddr_in peer` + `socklen_t len`，再用 `inet_ntop` 转成可读 IP）；顺手清掉久不说话的空闲连接把槽位还回来；实在不够就调大 `MAX_CONN` 或前面加代理。原则就是：宁可拒新连接，也不把已经连上的拖垮。
